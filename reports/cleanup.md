## 性能：实际下载与执行

固定 Linux ARM64、Playwright 1.57.0 / Chromium 143.0.7499.4，4 倍 CPU 降速、150 ms 延迟、200000 B/s 下载。使用真实本地 HTTP/gzip 镜像，字体响应字节相同，排除 CDN、DNS、TLS 波动；各版本新 context、关闭缓存，交替运行各 7 次，与视觉测试分开。数值为中位数；原始样本、范围与 MAD 见 [性能数据](validation/performance.json)。

| 首页指标 | 冻结参考 | 优化后 |
| --- | ---: | ---: |
| 请求数（不含统计脚本测试桩） | 18 | 12 |
| 运行时组件/论文数据请求 | 3 | 0 |
| 第一方 JS 源码字节，含内联 | 25,981 | 8,995（减少 65.4%） |
| 实际传输字节，含响应头 | 653,230 | 632,122（减少 3.2%） |
| FCP | 980 ms | 708 ms |
| LCP | 980 ms | 708 ms |
| CLS | 0.165499 | 0.144423 |
| 主线程脚本时间 | 29.014 ms | 25.321 ms |

本轮 FCP/LCP 改善 27.8%，参考范围 904–1124 ms、优化版 660–844 ms，超过本轮重复测量噪声。独立较早一轮同样观察到整体改善约 23.4%。主线程脚本耗时范围重叠较大，**不宣称 CPU 耗时显著改善**。这些是受控实验结果，不代表真实访客性能保证；CLS 也仍非零。

分阶段数据见 [消融记录](validation/ablation-performance.json)。组件单独预生成阶段的 FCP 中位数从 924 到 952 ms，7 对样本均略慢，尚未独立复核，不能声称每个单独阶段都加速。最终组合版本在两轮测量中均有明显加载改善；保留分阶段开关方便后续撤销，不隐瞒此限制。

## 复现与维护

命令与环境见 [README](../README.md) 和 [测试说明](../tests/README.md)。主要命令：

```sh
npm run reference
npm run build
npm test
npm run check
AA=1 REPORT=output/linux/aa.json npm run test:container
REPORT=output/linux/candidate.json npm run test:container
PERF_REPORT=output/linux/performance.json npm run test:container -- node scripts/performance.mjs
```

构建输出与静态资源检查会检查本地路径、字体字节、图标规则、统计 ID 和发布排除项。原有 URL 和 CNAME 保留。正常 Actions 发布运行构建、单元测试和功能检查；手动 `strict` 输入额外启用完整 A/A、动效关键帧与性能门槛，严格检查仍可能失败。Pages 使用 Actions 发布 Node 预构建产物，不再把未加工源码直接交给旧分支发布流程。提交/push、Actions 成功和线上实际更新分开核对，以 GitHub 运行记录与在线资源为发布证据。
